# 手写模板上传与字形提取技术方案

## 目标与范围

用户按模板填写一页 A4，上传扫描图或照片。系统自动校正页面、逐格提取笔迹、生成透明背景的字形图片，最后让用户检查并修正结果。本方案只覆盖**上传至字形库入库**；文字拼接和排版另行实现。

当前模板及其坐标数据：

- [A4 打印模板](../手写字母采集模板_A4.pdf)
- [格子坐标 JSON](../pkg/handwriting_concat/assets/template_v2.json)
- [模板生成脚本](../tools/generate_template.py)

模板版本为 `2`，单页 A4，共 20 行、395 个应填写的格子；末行尾部四格比普通格更宽，分别采集手写横线与斜线。末行另外有四个 `→` 格。正文与补写区共同保证每个大小写字母至少出现 3 次。**格子的目标字符由 JSON 指定，不依赖 OCR 或 GPT 猜测。**

## 技术选择

| 环节 | 主方案 | 原因 |
| --- | --- | --- |
| 页面定位、旋转、透视校正 | OpenCV ArUco + 单应性变换 | 定位码有确定的 ID 和毫米坐标，输出可复现的像素位置 |
| 逐格裁切 | JSON 坐标 + NumPy/OpenCV | 每格的字符、状态和安全边界都已知 |
| 去背景、透明化 | 图像处理；难例可加入专门的笔迹分割模型 | 需要保留真实笔画及边缘灰度，不能生成或重画字形 |
| 写错、漏写等质检 | 图像规则 + 可选视觉模型 + 用户确认 | 模型适合识别异常，不适合代替精确裁切与像素掩膜 |

GPT 不参与定位、切格或像素抠图的主路径。若加入视觉模型，只用于把**疑似异常**格子排到人工校对列表前面；模型判断不能直接覆盖模板给出的目标字符，也不能生成替代笔迹。是否加入模型，应以真实填写页的人工验收率来决定。

## 输入与坐标约定

- 支持 PNG、JPEG，以及单页 PDF 扫描件。处理时保留原图，另生成工作图。
- 建议 600 DPI 扫描；300 DPI 可作为最低推荐值。手机照片须包含完整四角定位码，避免反光、阴影、模糊和纸张弯曲。
- JSON 的坐标单位是毫米，原点位于 A4 页面左上角，页面尺寸为 `210 × 297 mm`。
- `registration_dictionary` 为 `DICT_4X4_50`；四角 ID 为左上 `11`、右上 `17`、左下 `23`、右下 `29`，每码宽高 `9 mm`。以 JSON 内的 `registration_markers` 为唯一坐标来源。
- 每个 `cells[]` 项包含 `row`、`column`、`character`、`write`、`occurrence`、`cell_bbox_mm` 和 `safe_bbox_mm`。`write: false` 的灰格直接跳过；空格也不产出字形。
- 模板和 JSON 必须按 `template_version` 配对。旧版四角黑块模板不应拿新版定位码配置处理。

推荐的标准页面尺寸：300 DPI 为 `2480 × 3508 px`，600 DPI 为 `4961 × 7016 px`。检测定位码时可以用降采样图提速，但最终校正和字形抠图应使用原图可提供的最高有效分辨率；不要靠放大低分辨率照片假装增加细节。

## 处理流程

### 1. 图像预检

1. 解码并处理 EXIF 方向；检查图像尺寸、清晰度、是否严重过曝或欠曝。
2. 尝试检测四个指定 ArUco ID。出现其他 ID 不能替代这四个。
3. 若定位码缺失或局部被裁切，给出具体提示，并提供重新拍照或手动标四角的入口。自动处理优先使用四码齐全的页面。

预检只判断是否有足够信息进入自动处理，不应静默裁掉纸边或任意猜测缺失的定位码。

### 2. ArUco 定位与页面校正

1. 使用 `cv2.aruco.getPredefinedDictionary(cv2.aruco.DICT_4X4_50)` 和 `cv2.aruco.ArucoDetector` 检测；可开启亚像素角点优化。
2. 依 ID 找到四个码，并把检测到的角点对应到 JSON 中各码的 `bbox_mm` 四角。统一坐标顺序，避免页面倒置时颠倒角点。
3. 将模板毫米坐标换算为标准页面像素坐标。收集四码的角点，使用 `cv2.findHomography(..., cv2.RANSAC)` 求照片至标准页面的单应矩阵，再用 `cv2.warpPerspective` 拉正整页。
4. 验证定位码重投影误差，并检查校正后若干已知格线、行列位置。单应变换只能处理平面透视；纸张起皱、弯曲或镜头畸变导致局部错位时，可增加网格线局部校正，或要求重新拍摄。

定位结果应保存检测到的 ID、角点、单应矩阵、输入尺寸、输出尺寸和质量指标，方便定位后续切格问题。质量阈值要用真实扫描与手机照片校准，不应只凭合成图定死。

### 3. 按坐标逐格裁切

校正后，遍历 JSON 的 `cells[]`。只处理 `write: true` 的项，并用 `safe_bbox_mm` 而不是外框 `cell_bbox_mm` 切图，以避开印刷边线。上方的提示字符也在裁切范围之外。

```python
for cell in layout["cells"]:
    if not cell["write"]:
        continue

    x1, y1, x2, y2 = cell["safe_bbox_mm"]
    left = round(x1 * page_width / 210)
    right = round(x2 * page_width / 210)
    top = round(y1 * page_height / 297)
    bottom = round(y2 * page_height / 297)
    crop = corrected_page[top:bottom, left:right]
    target_character = cell["character"]
```

这里的 `page_width`、`page_height` 必须是**校正后标准页面**的像素尺寸。对格子边缘再做一次检查：笔迹若碰到安全裁切边界，应标为需要复核，不能静默截掉笔画。

### 4. 笔迹分割与透明化

1. 在校正后的整页或局部格子上估计纸张底色与光照，消除缓慢变化的阴影。不要在分割前把原图粗暴转成纯黑白。
2. 对照当前模板的浅色边框、灰格和白色格内区域，建立印刷元素掩膜。格内若残留印刷线，优先使用已知模板位置或颜色特征排除。
3. 以纸色和黑色笔迹的亮度、颜色差异得到前景概率，保留抗锯齿边缘作为连续的 alpha 值。阈值可按整页纸色与笔色自适应，并保留原始裁图供回退。
4. 在**整个格子**内求笔迹包围盒，四周加少量透明边距后输出 RGBA PNG。`i`、`j`、`!`、`:` 等多连通域字符仍是一个样本，不按连通域拆成多个字形。
5. 去噪应保守：小墨点可能正是标点或 `i/j` 的点。无法确定是否为噪声时保留并标记复核。

为了后续自然拼接，除了紧裁后的 PNG，还要记录原笔迹在格子中的相对位置、原尺寸和基线参考。只保存紧裁图会丢失上下对齐信息。

### 5. 自动质检与用户校对

为每格计算并展示至少以下状态：

- `empty`：未检测到可靠笔迹。
- `touches_border`：前景碰到安全裁切边界，可能被截断或写到格线。
- `low_contrast`：笔迹太浅、背景不均或分割置信度低。
- `suspected_mismatch`：可选视觉模型怀疑写入字符与目标字符不符。
- `ok`：自动检查通过，仍允许用户修改。

校对界面按字符分组，**同时显示原格裁图与透明化结果**。用户可接受、删除、调整裁切/阈值、重新上传该页或补写某字符。模型质检只给出提示，最终由用户确认。没有有效版本的字符不能悄悄用印刷字体填充；应明确提示缺字。

### 6. 归档

文件夹名使用 Unicode 码点，避免大小写折叠和 `/`、`\\`、`?` 等标点作为路径名造成问题。例如：

```text
glyphs/
  U+0041/001.png     # A
  U+0061/001.png     # a
  U+002F/001.png     # /
manifest.json
```

`manifest.json` 至少记录：模板版本、字符与码点、样本编号、原行列、原始格坐标、笔迹包围盒、基线/相对位置、输出文件、质检状态以及用户是否接受。保存原始上传图和校正页面，以便重新分割而不要求用户再次填写。

## 模块边界

建议将实现分成以下可独立调试的模块：

```text
upload.py        文件校验、EXIF/PDF 解码、原件保存
registration.py  ArUco 检测、单应变换、页面质量检查
cells.py         JSON 校验、毫米转像素、逐格裁切
segmentation.py  去背景、笔迹 alpha、紧裁与对齐元数据
quality.py       空格、碰边、浅笔迹、疑似错字检测
storage.py       字形目录、manifest、用户接受状态
```

核心接口可以是 `extract_page(image, layout) -> corrected_page, samples, review_flags`。每个样本携带原图位置和处理参数，便于在校对界面重算。

## 验收与测试

1. **模板自检**：PDF 渲染到 160/300 DPI 后，OpenCV 能读出 `11/17/23/29`；旋转 180° 后仍能按 ID 正确定位。模板每格与 JSON 坐标一致。
2. **空白页测试**：空白打印页上传后，所有可写格都不应误产生笔迹。重点检查格线、提示字符和定位码不会进入裁图。
3. **合成变形测试**：对已知页面施加旋转、透视、亮度变化、轻微模糊，检查校正后格线位置与目标坐标的偏差。
4. **真实样本测试**：至少覆盖扫描、正常手机照片、斜拍、轻微阴影、浅笔迹、写错字和碰框。逐格对照原图，统计需要人工修改的比例与原因。
5. **关键字符测试**：专查 `i/j/!/:;` 等多部件字符、细竖线、点号、引号、括号及 `O/0`、`l/1` 等易混字符，确认不丢点、不粘格线、不误归类。

交付标准应以**人工验收后的有效字形比例**和**真实照片的自动定位成功率**衡量；在拿到实际填写页之前，分割阈值和质检阈值都属于待校准参数。
